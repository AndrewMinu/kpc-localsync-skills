# 시작하기 · AI와 일하는 법 (Agentic Workflow)

## 목적

**"AI가 다 해준다"가 아니라 "AI와 같이 만든다"** 를 첫날에 몸으로 겪게 한다.

좋은 AI 활용은 **한 번에 잘 묻는 것**이 아니다. **검토 기준을 설계하는 것**이다. 이걸 말로 설명하면 안 와닿는다. **같은 요청, 두 가지 결과**를 나란히 놓고 팀이 직접 보게 한다.

## 진행 흐름

```
① 맨몸 요청 (설치 전에 이미 해둠)
      ↓
② 체크리스트로 두들기기  ← 사람이 판단하는 지점
      ↓
③ 스킬로 재요청 ($trip-course)
      ↓
④ 결과 차이 평가 (비교표)
      ↓
⑤ "그래서 스킬이 뭔데?" — 열어보기
```

---

## ① 맨몸 요청 — 이미 갖고 있을 것

**이 실습은 스킬을 깔기 전에 이미 시작됐다.** 설치 전에 Codex에 맨몸으로 던진 그 요청 말이다.

> *"자, 아까 스킬 깔기 전에 '강릉 1박2일 코스 짜줘'만 던져서 받은 결과 있죠? 그거 좀 보여주세요."*

- **안 해왔으면** — 지금 새 대화창을 하나 열어서 시켜도 된다. 딱 그 한 문장만 던진다. 조건은 아무것도 주지 않는다.
- 결과를 **팀이 함께 볼 수 있게** 띄워둔다. 이게 우리의 '전(前)' 이다.

첫인상을 먼저 묻는다. *"어때요? 그럴듯해요?"* — 대부분 "괜찮은데요?" 라고 한다. **그게 정상이고, 그래서 이 실습을 한다.**

---

## ② 체크리스트로 두들기기 ★ 여기가 핵심이다

여기서 **AI가 판정하지 않는다.** 팀이 찾는다. 절대 먼저 답을 말해주지 말 것.

### 컬러 역할부터 나눈다

4인 팀 기준. 3인이면 White가 Green·Yellow를 겸한다.

| 역할 | 이 실습에서 볼 것 |
|---|---|
| 🔴 **Red** | 두 결과 중 어느 쪽이 더 쓸 만한지 **팀의 결론**을 정리한다 |
| 🔵 **Blue** | **현실성** — 동선·예산·시간·날씨·이동 피로도가 말이 되나 |
| 🟢 **Green** | **사용자** — 누구를 위한 코스인가? 취향·동행이 반영됐나 |
| 🟡 **Yellow** | **차이 설명** — 뭐가 왜 달라졌는지 팀이 이해하게 정리·공유 |

> 역할은 **순서대로 일하는 직무가 아니라, 같은 결과물을 서로 다른 렌즈로 동시에 보는 것**이다. 전원이 AI를 쓰고, 전원이 서로의 결과를 검토한다.

### 검토 체크리스트 — 팀이 직접 채운다

맨몸 초안을 놓고 하나씩 짚는다. **묻고 기다린다.**

| 확인할 것 | 됐나? | Blue/Green 코멘트 |
|---|---|---|
| **누구**를 위한 코스인지 물어봤나? (동행·취향) | | |
| **예산**을 물어봤나? | | |
| **차가 있는지** 물어봤나? | | |
| **날씨**를 고려했나? 비 오면 어쩌지? | | |
| 하루 이동 시간이 얼마나 되나? **걸어보면 될 만한가?** | | |
| **밥은 언제 어디서** 먹나? | | |
| 왜 이 순서인지 **근거**가 있나? | | |
| **문 닫았으면** 어쩌나? 대안이 있나? | | |

퍼실리테이션 질문:
- *"이 코스, 부모님 모시고 갈 수 있어요? 왜 아닐까요?"*
- *"내일 비 온다고 하면 이 일정 어떻게 돼요?"*
- *"하루에 여기 다 갈 수 있어요? 한번 이동시간 재보실래요?"*
- *"AI가 뭘 안 물어봤죠?"* ← **이 질문이 오늘의 핵심이다**

대개 **"아무것도 안 물어봤네"** 에서 팀이 조용해진다. 그 순간을 놓치지 말 것.

---

## ③ 스킬로 재요청

> *"자, 그럼 똑같은 걸 이번엔 스킬로 시켜볼게요. 요청 문장은 아까랑 똑같이 던져보세요."*

`$trip-course` 를 쓰게 한다. **같은 요청, 다른 도구.**

이번엔 AI가 **되묻는다** — 취향·동행·예산·이동수단·기간·날씨. 팀이 답하면 그걸 반영한 코스가 나온다. 이동시간이 적히고, 밥이 동선에 들어가고, 비 오는 날 대안이 붙는다.

*"방금 뭐가 달랐어요?"* — 팀이 먼저 말하게 한다.

---

## ④ 결과 차이 평가 — 비교표

Yellow가 주도해 채운다. **AI가 대신 채우지 않는다.**

| | 맨몸 요청 | 스킬 요청 |
|---|---|---|
| 조건을 물어봤나 | | |
| 이동 피로도 | | |
| 예산 반영 | | |
| 날씨 대안 | | |
| 근거 제시 | | |
| **팀 판정 (Red)** | | |

그리고 팀에게 묻는다:

- *"왜 이런 차이가 났을까요? AI가 갑자기 똑똑해진 걸까요?"*
- *"아니면 우리가 뭘 다르게 한 걸까요?"*

---

## ⑤ "그래서 스킬이 뭔데?" — 열어본다

여기서 **정답을 알려준다.** 팀이 충분히 겪은 다음이라 이제 와닿는다.

`trip-course` 스킬의 SKILL.md를 **직접 열어서 함께 읽는다.**

> *"마법 아니에요. 그냥 **글**이에요. 누가 미리 '이건 꼭 물어봐라, 이건 꼭 지켜라, 내놓기 전에 이거 확인해라'를 적어둔 거죠."*

짚어줄 것:
- **묻는 조건 6가지** — 사람이 미리 정한 것
- **지킬 규칙**(이동 2시간 이내, 대안 필수) — 사람이 미리 정한 것
- **스스로 검토 체크리스트** — 우리가 방금 손으로 한 걸, 스킬이 자동으로 한다

**그래서 결론은 이것이다:**

> **AI를 잘 쓰는 건 "잘 묻는 것"이 아니다. "무엇을 검토할지 정해두는 것"이다.**
> 앞으로 3일간 쓸 스킬도 전부 이렇게 생겼다. 그리고 여러분도 이런 걸 만들 수 있다.

---

## 산출물 (팀이 남긴다)

1. **비교표** — 맨몸 vs 스킬
2. **검토 체크리스트** — 채워진 것
3. **개선 피드백 문장** — *"AI 초안에 ○○가 빠져서, △△를 확인해달라고 다시 요청했다"* 형태로 팀당 1~2문장
4. **컬러 역할 배정표**

## 끝맺음

- *"오늘 배운 게 하나예요 — **AI가 낸 걸 그대로 쓰지 않는다.** 검토하고, 되묻고, 다시 시킨다. 3일 내내 이걸 합니다."*
- 다음은 **1단계 주제 선정** — `$topic-select`. 이제 진짜 우리 문제를 고른다.
- 아직 시간이 남으면 팀과 더 이야기해도 좋다:
  - *"우리 팀이라면 `trip-course`에 뭘 더 넣고 싶어요?"* (실제로 SKILL.md를 고쳐봐도 된다)
  - *"평소에 AI한테 실망했던 적 있어요? 그때 뭐가 빠졌던 걸까요?"*

## 톤·태도

- **답을 먼저 주지 않는다.** 팀이 찾을 때까지 질문으로 민다. 침묵을 견딘다.
- 맨몸 결과를 **비웃지 않는다.** "이것도 나쁘진 않죠 — 근데 우리가 쓸 수 있나요?" 정도가 좋다.
- 전원이 말하게 한다. 조용한 사람에게는 역할(Blue/Green)을 근거로 콕 집어 묻는다.
