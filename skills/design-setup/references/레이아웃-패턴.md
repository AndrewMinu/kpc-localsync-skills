# 레이아웃·컴포넌트 패턴 (참고)

> `design-setup`에서 색·서체를 정한 뒤, 화면을 짤 때 참고하는 패턴집.
> prototype-build / pitch-deck-build가 필요할 때 열어본다.

## 2. 레이아웃 원칙
- **최대폭 컨테이너**(720~960px) 가운데 정렬. 전체폭 방치 금지.
- 명확한 **위계**: 히어로(핵심 메시지+핵심 수치) → 섹션별 h2 → 카드 그리드.
- **그리드**: `repeat(auto-fill,minmax(210px,1fr))`로 카드 반응형.
- 한 화면 = 한 목적. 스크롤로 흐름을 만든다.

## 3. 컴포넌트 패턴
- **히어로**: 그라디언트 배경 + 제목 + 한 줄 소개 + **핵심 지표 3~4개 스탯칩**(데이터로 신뢰 주기).
- **칩/필터**: 선택 상태 뚜렷(테두리→채움 전환).
- **결과 카드**: 배지(강조 라벨)·제목·태그·설명. 강조 대상은 좌측 컬러바나 골드 배지로 차별.
- **빈 상태**: "무엇을 하면 되는지" 안내 문구(빈 화면 방치 금지).
- **마이크로 인터랙션**: hover/active 트랜지션 .15s, 버튼 눌림 피드백. 과하지 않게.

## 4. 피칭덱 크래프트
- **1슬라이드 1주장.** 설명하지 말고 주장한다 — 흐름과 장별 작법은 `pitch-deck-build`가 정한다.
- 고정 **슬라이드 프레임**: 섹션 라벨(작게) → **명사형 큰 제목** → **주장 2~3문장** → 본문 하나 → 우상단 페이지.
  전 슬라이드 동일 골격 → 일관성. 제목에 서술어를 넣지 않는다(`펫 동반 필터` ○ / `필터를 만들었습니다` ×) —
  주장은 그 아래 2~3문장이 편다. 거기에 **긴장 → 결정 → 이유**가 들어간다.
- **데이터 슬라이드엔 차트 1개** — 비교/분포를 시각화. 축·범례 색을 테마와 맞춤.
  **인라인 SVG 또는 CSS 막대로 그린다. 차트 라이브러리(Chart.js 등)를 불러오지 않는다** — 발표장
  네트워크가 끊기면 하필 데이터 근거 슬라이드만 비게 된다. 막대 그래프는 `<div>` + `width:87%` 로 끝난다.
- 흐름: One-liner → Problem → **Insight** → Product → Demo → The Ask (YC 데모데이 6비트).
  장 수는 팀이 정한다 — 이 개수를 따라가지 않는다. 자세한 건 `../../pitch-deck-build/SKILL.md`의 구성 절.
- **이동 UI를 화면에 두지 않는다.** 하단 4px 진행바만. 화살표 버튼·키보드 안내문은 발표 중에
  심사위원 눈을 뺏는다. 페이지 번호는 슬라이드 안 우상단에.
  이동·진행바·편집 구현은 `../../pitch-deck-build/references/덱-골격.md`를 복붙한다.

## 5. 폴리시 체크리스트 (산출 전 자가점검)
- [ ] 색은 3~4색 이내로 절제됐나(무지개 금지).
- [ ] 여백이 충분한가(요소가 서로 안 붙어 있나).
- [ ] 타이포 위계가 보이나(제목/본문/캡션 구분).
- [ ] 핵심 수치가 히어로/데이터슬라이드에 크게 보이나.
- [ ] hover/선택 등 인터랙션 피드백이 있나.
- [ ] 빈 상태·모바일 폭에서도 깨지지 않나.
- [ ] 외부 이미지·localStorage 없이 오프라인으로 뜨나.
- [ ] 슬라이드 골격이 전부 일관된가.

## 6. 안티패턴 (피하기)
빽빽한 여백, 5색 이상 남발, 기본 파랑 링크/기본 버튼 방치, 전체폭 텍스트 벽, 저해상 외부 이미지, 슬라이드마다 다른 레이아웃, 애니메이션 과다.

> 요약: **절제된 색 · 넉넉한 여백 · 뚜렷한 위계 · 큰 핵심 수치 · 일관된 슬라이드 골격.** 이 다섯이 데모 완성도의 90%.
