# 여행 코스 설계 (trip-course)

## 이 스킬이 하는 일

여행 코스를 짠다. 단, 두 가지를 지킨다: **묻지 않고 짜지 않고, 지어내서 짜지 않는다.**

AI에게 "코스 짜줘"라고만 하면 그럴듯한 일정이 바로 나온다. 문제는 그 일정이 누구를 위한 것도 아니고(예산·동행·날씨를 모른다), 그 장소가 진짜인지도 모른다는 것(기억으로 지어낸다). 이 스킬은 **조건을 먼저 확인하고, 실제 데이터를 호출해서, 근거 있는 코스를 조립하는 작업 지시서**다.

## 부트캠프 온보딩 실습 (참가자 첫 실행이면 여기부터)

부트캠프 참가자가 처음 실행한 것 같으면(설치 직후, "강릉 코스" 같은 실습 요청, 또는 실습이라고 말함) **`references/온보딩-실습.md`를 읽고 그 진행안대로 실습을 이끈다**: 맨몸 초안 검토 → 체크리스트 → 이 스킬의 본 워크플로우로 재실행 → 비교표 → 스킬 열어보기. 실습이 아니라 그냥 코스가 필요한 사용자면 이 섹션은 건너뛴다.

## 워크플로우 (이 순서대로)

```
① 조건 확인 (6가지, 비면 묻는다)
      ↓
② 데이터 호출 (장소 + 상세 + 혼잡도 + 날씨)   ← 키 있을 때
      ↓
③ 웹검색 보강 (가능하면 — 영업 여부·평판·행사)
      ↓
④ 코스 조립 (규칙 지키며)
      ↓
⑤ 스스로 검토 → 출력
```

## ① 반드시 확인할 6가지 (하나라도 비면 묻는다)

| # | 조건 | 안 물으면 생기는 일 |
|---|---|---|
| 1 | **취향** — 뭘 좋아하나? (자연/미식/역사/액티비티/휴식) | 남의 여행이 된다 |
| 2 | **동행** — 누구랑? (혼자/친구/연인/부모님/아이) | 부모님 모시고 등산 3시간 |
| 3 | **예산** — 얼마나 쓸 수 있나? | 1박 30만원 숙소를 아무렇지 않게 넣는다 |
| 4 | **이동수단** — 차가 있나 없나? | 차 없는 사람에게 버스 안 다니는 곳을 추천한다 |
| 5 | **기간·시간** — 며칠, 몇 시부터 몇 시까지? | 하루에 8곳을 넣는다 |
| 6 | **날씨·계절** — 언제 가나? | 비 오는 날 야외만 가득한 일정 |

**모르면 넘겨짚지 말고 묻는다.** 한 번에 다 묻지 말고, 대화하듯 2~3개씩 나눠 묻는다.

## ② 데이터를 호출한다 (지어내지 않는다)

공공데이터포털 키가 있으면(환경변수 `DATA_GO_KR_SERVICE_KEY` 또는 사용자가 준 키) **실데이터로 짠다**. 호출 명령은 `references/api-호출.md`를 읽고 그대로.

1. **지역 코드** — `areaCode2`로 대상 지역의 시도·시군구 코드를 확인한다.
2. **장소 후보** — `areaBasedList2`로 관광지(12)·문화시설(14)·음식점(39)·숙박(32)을 받는다. 취향에 맞는 유형만 골라 호출한다. 동행이 반려동물·휠체어·유아차면 펫/무장애 API로 필터한다.
3. **상세 확인** — 코스에 넣을 후보만 `detailIntro2`로 운영시간·쉬는날·주차를 확인한다. 방문일이 휴무면 그 자리에서 뺀다.
4. **혼잡도 예보** — 집중률 API로 방문일의 붐빔을 확인한다(30일 예보). 혼잡 90 이상인 곳은 시간대를 바꾸거나 대안을 먼저 제안한다.
5. **날씨·일몰** — 방문일이 예보 범위(3일 내)면 기상청 단기예보로 실측하고, 일몰 명소·야간 일정이 있으면 일출몰 API로 시각을 박는다. 범위 밖이면 계절 지식으로 대신하되 그렇게 표기한다.

받은 실측은 코스에 **근거로 표기**한다: *"○○(혼잡 41, 이번 주말 한산)"*. 지식으로 아는 장소여도 목록에 없으면 "API 미등록, 확인 필요"라고 솔직히 적는다.

**키가 없으면** — 그래도 짠다. 대신 첫 줄에 *"⚠ 실측 아님(키 없음): 장소·운영 여부를 직접 확인하세요"* 를 박고, `$tourapi-key`로 키를 만들면 실데이터 버전으로 업그레이드된다고 안내한다.

## ③ 웹검색으로 보강한다 (가능한 환경이면)

API가 못 주는 것을 웹검색으로 채운다: 식당·카페의 **평판**(API 등록이 곧 맛집은 아니다), 후보지의 **최근 영업 여부**(폐업·임시휴무), 방문일에 열리는 **행사·팝업**. 코스에 확정으로 넣는 장소는 최소한 "최근에도 영업 중인가"를 한 번 확인한다. 웹검색이 안 되는 환경이면 건너뛰되, `[놓친 것]`에 "영업 여부 미확인"을 적는다.

## ④ 코스를 짤 때 지킬 것

- **이동 피로도를 계산한다** — 장소 사이 이동 시간을 실제로 적는다(도보 15분, 버스 40분). 하루 총 이동이 **2시간을 넘으면 경고**한다. 하루 **3~4곳이 현실적**이다.
- **식사 시간을 비워두지 않는다** — 점심·저녁을 동선 위에 놓는다. "알아서 드세요"는 코스가 아니다.
- **대안을 반드시 함께 낸다** — 비 오면(실내 1곳) / 문 닫았으면(대체지 1곳) / 여유·피로(추가 1, 생략 1).
- **근거를 붙인다** — 왜 이 순서인지 한 줄. 혼잡도·거리·운영시간 같은 **데이터 근거**가 최고다.

```

Day 1

   ↓ 도보 15분

   ↓ 버스 25분
 14:00   □□□
 ...
 하루 총 이동: 1시간 20분 · 방문 4곳

[대안]
```

## 스스로 검토 (내놓기 전에 반드시)

- [ ] 6가지 조건을 다 확인했다(모르면 물었다).
- [ ] 장소가 실데이터에서 왔다(또는 ⚠실측 아님을 명시했다).
- [ ] 확정 장소의 운영시간·휴무를 확인했다(방문일 휴무인 곳이 없다).
- [ ] 이동 시간이 장소마다 적혀 있고, 하루 총합이 2시간 이내다.
- [ ] 하루 방문지가 3~4곳이고, 식사가 동선 위에 있다.
- [ ] 비 올 때 대안이 있다.
- [ ] 각 장소에 근거가 한 줄씩 있다(데이터 근거 우선).
- [ ] 예산이 사용자가 말한 범위 안이다.

**하나라도 못 지켰으면 내놓지 말고 고친다.** 고칠 수 없으면 `[놓친 것]`에 솔직히 적는다.
