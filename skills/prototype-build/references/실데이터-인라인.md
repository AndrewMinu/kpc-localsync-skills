# 실제 데이터를 화면에 넣는 법 (정적 인라인 · 동적 서버 경로)

> `prototype-build`의 심화 참고 문서. 실제 수치·장소·혼잡도를 화면에 올릴 때 읽는다. `prototype.html` 기준선과 정적 배포는 인라인 방식을, 동적 앱은 서버 경로와 인라인 폴백을 쓴다.

## ⚠ 브라우저에서 TourAPI를 직접 부르면 안 된다 (CORS)
`apis.data.go.kr`은 CORS 헤더를 주지 않는다. **브라우저에서 직접 fetch하면 실패한다** — 로컬에서 열든, 배포된 사이트에서든 똑같다. 키를 HTML이나 브라우저 번들에 박는 것도 금물이다(배포하면 전 세계에 노출된다). 동적 앱은 브라우저가 아니라 **서버 경로**에서 호출한다.

## 정적 기준선: 데이터를 HTML 안에 넣는다
1. **터미널에서 한 번** 호출한다(키는 `.env`에만 남는다).
   ```bash
   curl -s "https://apis.data.go.kr/B551011/TatsCnctrRateService/tatsCnctrRatedList?serviceKey=$DATA_GO_KR_SERVICE_KEY&numOfRows=1000&pageNo=1&MobileOS=ETC&MobileApp=ftskill&_type=json&areaCd={행정시도}&signguCd={행정시군구}"
   ```
   ⚠ `baseYm`을 넣으면 에러다. 응답: `tAtsNm`·`baseYmd`·`cnctrRate`(100=가장 붐빌 때).
2. 받은 값을 **`prototype.html` 스크립트 안에 `const DATA = [...]` 로 인라인**한다.
   > **별도 `data.json` 파일을 두지 마라.** `file://`로 열면 로컬 JSON fetch도 CORS로 막힌다(origin `null`). **파일 하나, 더블클릭이면 열린다** — 단일 파일 원칙과도 맞는다. 정적 원본 보존 방식으로 Sites에 배포할 때는 이 파일을 최소 포장 프로젝트에 바이트 단위로 복사한다(`sites-배포.md`).
3. 공급 데이터(관광지·음식·숙박 목록)도 같은 방식으로 받아 인라인한다.
4. 팀에 물어라: *"어떤 데이터를 화면에 올려야 우리 주장이 한눈에 보일까요?"*

## 동적 앱이라면: 서버에서 호출하고 스냅샷을 남긴다

1. API 키는 Sites의 **서버 쪽 비밀 설정**에 두고, 공개 파일·브라우저 코드·로그에 값이 나타나지 않게 한다.
2. `site/`의 서버 경로가 TourAPI를 호출하고 필요한 필드만 브라우저에 돌려준다. 브라우저에서 TourAPI를 직접 호출하지 않는다.
3. 로딩·오류·빈 상태를 화면에 만든다. 외부 API가 느리거나 멈춰도 시연이 중단되지 않도록 마지막 검증 응답을 정적 스냅샷으로 둔다.
4. `prototype.html`의 인라인 데이터는 오프라인 폴백으로 유지한다. 동적 앱 전환 때문에 기준선을 지우지 않는다.
5. `context.md`에 실시간 호출 범위, 스냅샷 기준시점, 외부 API 실패 시 동작을 적는다.

## 혼잡도 붙이기 (쏠림·계절·분산·코스 주제라면 강력 추천)
집중률 API는 **호출한 날부터 30일치 예보**를 준다 → *"이번 주말 여긴 붐빔(98), 대신 여기 어때요(41)"* 를 화면에 그대로 띄울 수 있다. 데모가 확 산다. 30일 예보라 **부트캠프 3일 내내, 심사 시점에도 유효하다.** 실시간처럼 보이고 실제로도 맞다.

## 피칭 때 한 줄 (심사위원이 좋아한다)
- 정적 방식: *"지금은 받아둔 데이터를 넣어 안정적으로 시연하고, 실서비스에선 서버가 API를 대신 호출해 갱신합니다."*
- 동적 방식: *"브라우저에 키를 노출하지 않고 서버가 API를 호출하며, 장애 때는 검증된 스냅샷으로 시연이 이어집니다."*

정적 인라인은 실패가 아니라 **검증 범위를 의도적으로 제한한 선택**이다. 어떤 방식을 택했는지와 한계를 팀이 정확히 말하면 신뢰가 올라간다.

## 완성도 올리기 (시간 있으면)
- 반응형 · 빈 상태 · 로딩 · 마이크로 인터랙션 · 접근성(대비·글자 크기).
- 2~3차 iteration: 오피스아워 사이에 계속 다듬는다(한 번에 끝내지 않는다).
