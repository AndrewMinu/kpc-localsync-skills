# 실제 데이터를 화면에 넣는 법 (CORS 우회 · 인라인 방식)

> `prototype-build`의 심화 참고 문서. 실제 수치·장소·혼잡도를 화면에 올릴 때 읽는다.

## ⚠ 브라우저에서 TourAPI를 직접 부르면 안 된다 (CORS)
`apis.data.go.kr`은 CORS 헤더를 주지 않는다. **HTML에서 fetch하면 무조건 실패한다** — 로컬에서 열든, 배포된 사이트에서든 똑같다. 키를 HTML에 박는 것도 금물(배포하면 전 세계에, 업로드하면 다른 팀에 그대로 노출된다).

## 대신: 데이터를 HTML 안에 박는다 (이게 정답이다)
1. **터미널에서 한 번** 호출한다(키는 `.env`에만 남는다).
   ```bash
   curl -s "https://apis.data.go.kr/B551011/TatsCnctrRateService/tatsCnctrRatedList?serviceKey=$DATA_GO_KR_SERVICE_KEY&numOfRows=1000&pageNo=1&MobileOS=ETC&MobileApp=ftskill&_type=json&areaCd={행정시도}&signguCd={행정시군구}"
   ```
   ⚠ `baseYm`을 넣으면 에러다. 응답: `tAtsNm`·`baseYmd`·`cnctrRate`(100=가장 붐빌 때).
2. 받은 값을 **`prototype.html` 스크립트 안에 `const DATA = [...]` 로 인라인**한다.
   > **별도 `data.json` 파일을 두지 마라.** `file://`로 열면 로컬 JSON fetch도 CORS로 막힌다(origin `null`). **파일 하나, 더블클릭이면 열린다** — 단일 파일 원칙과도 맞고, 배포할 때도 파일 하나만 올리면 된다.
3. 공급 데이터(관광지·음식·숙박 목록)도 같은 방식으로 받아 인라인한다.
4. 팀에 물어라: *"어떤 데이터를 화면에 올려야 우리 주장이 한눈에 보일까요?"*

## 혼잡도 붙이기 (쏠림·계절·분산·코스 주제라면 강력 추천)
집중률 API는 **호출한 날부터 30일치 예보**를 준다 → *"이번 주말 여긴 붐빔(98), 대신 여기 어때요(41)"* 를 화면에 그대로 띄울 수 있다. 데모가 확 산다. 30일 예보라 **부트캠프 3일 내내, 심사 시점에도 유효하다.** 실시간처럼 보이고 실제로도 맞다.

## 피칭 때 한 줄 (심사위원이 좋아한다)
*"지금은 받아둔 데이터를 넣어 보여드리지만, 실서비스에선 **서버가 API를 대신 호출**해 매일 갱신합니다."*
→ 정적 데이터는 '진짜 앱의 방식'이 아니라 **서버 없이 데모를 만드는 우회로**다. 이 한계를 팀이 알고 말하면 신뢰가 올라간다.

## 완성도 올리기 (시간 있으면)
- 반응형 · 빈 상태 · 로딩 · 마이크로 인터랙션 · 접근성(대비·글자 크기).
- 2~3차 iteration: 오피스아워 사이에 계속 다듬는다(한 번에 끝내지 않는다).
