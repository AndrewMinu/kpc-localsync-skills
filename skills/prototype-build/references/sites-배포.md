# Codex Sites 배포 절차

> `prototype-build`의 배포 참고 문서. 핵심 기능 1개가 로컬에서 돌면 이 문서대로 배포한다.

## 왜 배포하나
발표에서 "파일을 열어 보여드릴게요"와 "주소로 들어와 보세요"는 무게가 다르다. URL이 있으면 심사위원·다른 팀이 자기 폰으로 직접 눌러볼 수 있고, 실현 가능성(30점)에서 "이미 돌아가는 서비스"로 읽힌다.

## 배포 전 체크 (1분)
- [ ] `prototype.html` **파일 하나**로 완결되나? (외부는 CDN만, 데이터는 인라인)
- [ ] HTML 안에 **API 키가 없나?** (배포 = 전 세계 공개. 있으면 지금 빼라)
- [ ] 더블클릭으로 열었을 때 핵심 기능 1개가 도나?

## 배포 절차
> ⚠ **[FT 확정 필요]** 아래 절차는 캠프 전 FT가 Codex Sites를 실측한 뒤 정확한 명령·클릭 경로로 갱신한다. 참가자는 이 박스가 채워진 버전을 받는다.
1. Codex에서 프로젝트 폴더(또는 `prototype.html`)를 연 상태에서 Sites 배포를 요청한다. *(정확한 진입점: FT 갱신)*
2. 배포가 끝나면 나오는 **URL을 복사**한다.
3. 수정 후 재배포도 같은 절차 — 배포는 몇 번이든 다시 할 수 있다.

## 배포 후 체크 (2분)
- [ ] 팀 전원이 **자기 폰**으로 URL을 연다.
- [ ] 데이터가 다 보이나? (인라인 방식이면 무조건 보인다 — 안 보이면 fetch를 쓰고 있다는 뜻, `실데이터-인라인.md` 다시)
- [ ] 모바일에서 깨지는 곳 체크 → 다음 반복에서 수정.
- [ ] URL을 `context.md`와 발표 덱에 기록.

## 안 되면 (폴백 — 발표는 멈추지 않는다)
1. 5분 안에 해결이 안 보이면 **FT를 부른다.**
2. 발표 준비는 **로컬 더블클릭 데모**로 계속 간다 — 우리 파일은 오프라인에서도 열리게 만들었다. 배포는 가산점이지 필수 조건이 아니다.
3. 여유가 생기면 다시 시도한다.
