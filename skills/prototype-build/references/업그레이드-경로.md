# 업그레이드 경로 — 기본 트랙 이후의 다음 계단 (선택)

> `prototype-build`의 심화 참고 문서. **공개 배포 또는 로컬 폴백 검증으로 6단계를 끝냈고 시간이 남는 팀**만 본다. 시작 전에 FT와 남은 시간 대비 어디까지가 현실적인지 합의하라 — 계단을 오르다 발표를 놓치면 본전도 못 찾는다.

단, `idea-validate`에서 확정한 핵심 기능 자체가 인증·DB·서버 API·업로드·실시간 동작을 요구한다면 동적 앱은 업그레이드가 아니라 **6단계의 배포 방식**이다. 이 경우 정적 배포를 먼저 끝낼 필요 없이 `sites-배포.md`의 동적 앱 방식으로 간다.

## 우리 팀은 지금 어디인가
- **L1 · 보이는 것** — 목업 + 인라인 데이터 + (로그인 없이 검증한 공개 URL 또는 검증된 로컬 폴백). ← 기본 트랙 완주 지점
- **L2 · 진짜 데이터** — 실측 데이터가 화면의 주장을 만든다. 필요하면 서버 경로로 안전하게 갱신한다.
- **L3 · 진짜 에이전트** — 사용자와 대화하며 조건을 파악하고 결과를 만든다. 대개 동적 앱이 필요하다.

피칭 때 자기 레벨을 명시하면("저희는 L2까지 구현했고, L3는 이렇게 확장합니다") 심사위원이 완성도를 정확히 읽는다.

## L2 · 진짜 데이터 (반나절)
목표: "예시 데이터"가 아니라 **실측이 화면의 주장을 만드는 상태.**
- 카테고리·지역을 넓혀 인라인 데이터를 두껍게: 관광지+음식+숙박+행사를 함께 받아 코스 생성이 실데이터로 돌게 한다. (방법은 `실데이터-인라인.md` 그대로 — 호출만 늘리면 된다)
- 혼잡도 30일 예보를 붙여 "오늘 기준" 추천이 되게 한다.
- 데이터랩에서 받은 수치(방문 추이·숙박비중)를 화면 상단에 근거 카드로 박는다 — 말로 설명할 문제를 화면이 대신 증명한다.
- 최신 조회가 핵심이면 동적 앱으로 전환해 서버 경로에서 호출한다. 키는 서버 쪽 비밀 설정에 두고, 시연용 검증 스냅샷은 남긴다.

## L3 · 진짜 에이전트 (반나절~, FT 상의 필수)
목표: 폼 입력이 아니라 **대화로** 조건을 받고, 도구(내장 데이터 검색·필터)를 호출해 답을 만드는 화면.
- 1단계 — 대화형 입력: 자유 텍스트 입력("혼자 가고, 매운 거 못 먹어요")을 받아 조건을 뽑아 기존 필터에 넘긴다.
- 2단계 — 도구 호출 구조: 에이전트가 [데이터 검색 → 필터 → 코스 조립]을 단계로 밟고, 화면에 "지금 무엇을 하는 중인지" 보여준다. 이 과정 표시 자체가 '에이전틱함'의 데모다.
- 3단계 — RAG 해설·다국어: 장소 설명·문화 맥락·외국어 카드를 생성해 붙인다.
- ⚠ LLM API를 앱에서 직접 호출하는 건 **키·비용 문제가 있으니 반드시 FT와 먼저** — 키 없이 데모하는 방법(사전 생성 응답, 시나리오 모드)이 더 나을 수 있다.

동적 앱으로 바꿀 때는 `prototype.html`을 기준선·오프라인 폴백으로 보존하고, `sites-배포.md`의 제품 계약과 의도된 차이 기록을 따른다. Sites가 지원하는 `vinext/React` 구조나 기존 호환 구조를 쓸 수 있지만 프레임워크 전환 자체가 업그레이드 목표는 아니다.

## 다른 방향 — 사용자를 바꾸기
기능을 쌓는 대신 **같은 문제를 운영자(상인·사무국) 시점에서** 푸는 확장도 있다. FT에게 물어보라. 예: 야간 코스 앱(여행자용)에 야간 상권 사장님용 홍보 카드 생성기를 붙이면 서비스의 양면이 생긴다.
