# 기준데이터 — 전국 234개 시군구 × 31개 지표

**이 데이터는 AI의 내부 검증용이다.** 팀이 지역·이슈를 입에 올릴 때 조용히 조회해서 "내 추천이 데이터
위에 서 있는지" 확인하는 데 쓴다. **숫자를 참가자에게 늘어놓지 않는다** — 참가자는 4단계에서 자기 키로
직접 받아 검증한다. 그 발견의 경험을 여기서 뺏지 않는다.

모든 파일은 `region_id`(예: `36-17` = 통영시)로 조인된다. `regions.csv`가 지역 이름↔코드 사전이다.

## 읽기 전에 — 반드시 아는 다섯 가지

**① 코드가 두 종류다.** TourAPI 지역코드와 행정 시군구코드는 다르다.
- **TourAPI 코드** — 공급(`areaBasedList2`)·무장애. `regions.csv`의 `area_code`/`sigungu_code`.
- **행정 코드** — 수요강도·동선·집중률. 예: 서울 `11`, 구로 `11530`. 창원은 경남 `48`.

**변환은 `region_admin.csv`로 한다.** 손으로 짐작하지 않는다.

**② 통합시는 1:N이다.** 수요지수 API가 **구 단위로만** 값을 주는 시가 12곳 있다 — 수원·성남·고양·
용인·창원·청주·천안·전주·포항·안산·안양·부천. `region_admin.csv`에서 여러 행으로 나온다.

```
36-16(창원시) → areaCd=48 · signguCd 48121 48123 48125 48127 48129 (5개 구)
```

이 CSV의 창원 값은 그 5개 구의 **단순평균**이다. 라이브로 다시 부르면 구가 따로 나오니 숫자가 안 맞아
보인다 — 틀린 게 아니라 집계 단위가 다른 것이다. 팀에게 이걸 짚어주면 좋은 데이터 리터러시 수업이 된다.

**③ 수요 데이터는 229개다.** 공급은 234개 전부 있지만 **방문·수요강도·동선은 229개**다.
빠진 5개는 **폐지된 행정구역**이라 행정코드가 없다 — TourAPI가 legacy 코드를 유지할 뿐이다.

| region_id | 이름 | 사정 |
|---|---|---|
| `33-9` | 청원군 | 2014 청주시 통합 |
| `36-6` · `36-14` | 마산시 · 진해시 | 2010 창원시 통합 |
| `39-1` · `39-2` | 남제주군 · 북제주군 | 2006 서귀포시·제주시 통합 |

팀이 이 지역을 고르면 통합된 현재 지역으로 안내한다. **빈 값을 0으로 읽지 않는다.**

**④ 지수는 %도 금액도 아니다.** `(지수)` 붙은 값은 전부 상대 지수다. 100을 넘을 수 있다
(서울 중구 소비 199 vs 농촌 62~68). **절대값으로 단정하지 말고 지역 간 비교·순위로만** 쓴다.

**⑤ 공급은 등록 건수다.** 실제 시설 총량이 아니고, 개수가 많다고 수요가 많은 것도 아니다.

> ⚠ **2026년 행정개편** — 광주+전남이 `전남광주통합특별시`(코드 12)로 통합됐다. 시도코드로만 집계하면
> 두 지역이 0으로 보인다. 이름 기준으로 되돌려 붙일 것.

## 수집 메모

**기준 시점** — 공급·다양성·수요강도 = `202509`. 방문자수 = 최근 연간(`2025-06~2026-05`).
축제는 시점 변동이 커서 스냅샷이다.

**쓰지 않은 데이터 ①: 의료관광** — 331건 중 서울 214건(65%)·부산 38건 편중. 나머지 지역은
0~한 자릿수라 지역 이슈로 성립하지 않아 기준데이터에서 제외했다.
단, 카드 **E6**(의료·웰니스)를 고른 팀은 **라이브로 직접 받아 검증**한다.

**쓰지 않은 데이터 ②: 관광지 집중률** — 조회일부터 30일치 **예측**이라 시점마다 값이 바뀐다.
고정 근거로 부적합해서 뺐다. 대신 **참가자가 프로토타입에서 실시간 혼잡도 기능으로 쓴다.**
30일 예보라 부트캠프 3일 내내, 심사 시점에도 유효하다.
