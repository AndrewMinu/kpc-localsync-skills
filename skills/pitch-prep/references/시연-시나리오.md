# 시연(데모) 시나리오 짜는 법

> `pitch-rehearse` ②단계의 상세 참고 문서. 발표의 데모 구간(약 1분 30초)을 초 단위로 설계한다.

## 무엇을 보여줄 것인가 — 🟢

*"우리 화면에서 딱 하나만 보여줄 수 있다면 뭐예요?"*

**전부 보여주려 하면 아무것도 안 남는다.** 기능 나열이 아니라 **한 사람의 이야기**를 보여준다.

> ❌ *"필터 기능이 있고요, 지도도 있고요, 추천도 되고요…"*
> ✅ *"통영에 온 지연 씨는 저녁에 뭘 먹을지 몰라 편의점에 갔습니다. 이 화면을 켜면…"*

*"우리 페르소나가 이 화면을 처음 여는 순간, 뭘 보고 뭘 누를까요? 그대로 따라가봅시다."*

## 클릭 시나리오 — 한 스텝씩 적는다

**말로만 하면 무대에서 반드시 꼬인다.** 실제 클릭을 순서대로 적는다.

| # | 화면에서 하는 것 | 말할 대사 (한 줄) | 걸리는 시간 |
|---|---|---|---|
| 1 | 화면을 연다 (배포 URL이면 더 좋다) | *"통영에 온 여행자가 저녁에 뭘 할지 막막합니다"* | 10초 |
| 2 | ○○를 누른다 | *"취향을 고르면"* | 5초 |
| 3 | 결과가 뜬다 | *"근처 로컬 식당 세 곳이 동선 위에 뜹니다"* | 15초 |
| 4 | △△를 보여준다 | *"여기 이 숫자가 아까 보신 그 데이터예요"* ← **데이터 연결** | 10초 |

**규칙:**
- **90초를 넘기지 않는다.** 넘으면 스텝을 줄인다.
- **한 스텝 = 한 클릭 = 한 문장.** 클릭하면서 두 가지를 설명하면 아무도 못 따라온다.
- **마지막 스텝은 반드시 "그래서 문제가 풀렸다"** 로 끝난다.

## 데이터를 화면에 연결한다 — 🔵

**이게 이 부트캠프의 채점 포인트다.** 예쁜 화면만 보여주면 "그래서 근거는?"이 나온다.

시연 중 **최소 한 번은** 이렇게 말해야 한다:
> *"여기 이 추천이 나온 이유는, 아까 보신 그 데이터 때문입니다."*

*"우리 시연 어느 대목에서 데이터를 짚을까요?"* — 정확히 한 스텝을 골라 표에 표시한다.

## 플랜 B — 🔵 (반드시)

**데모는 무대에서 깨진다.** 대비 안 하면 그 자리에서 얼어붙는다.

| 사고 | 대비 |
|---|---|
| **인터넷이 안 된다** | 우리 파일이 오프라인에서 열리나? **지금 와이파이 끄고 테스트해본다.** (배포 URL로 시연할 계획이어도 로컬 파일을 예비로) |
| **화면이 안 뜬다 / 버튼이 안 먹는다** | **스크린샷을 미리 찍어둔다.** 최소 3장 — 시작·중간·결과. 슬라이드에 넣어둔다. |
| **노트북이 안 붙는다** | 파일을 다른 팀원 노트북에도 복사해둔다. |
| **시간이 반으로 줄었다** | 90초 → **30초 축약판**을 미리 정해둔다. 어느 스텝을 뺄지 지금 고른다. |

*"지금 와이파이 끄고 한번 열어볼까요?"* ← 이거 꼭 시킨다. 여기서 걸리는 팀이 매년 나온다.

## 역할 분담 — 🔴

| 역할 | 누가 | 하는 일 |
|---|---|---|
| **말하는 사람** | | 대사를 친다. 화면을 안 본다 — 심사위원을 본다. |
| **클릭하는 사람** | | 말없이 클릭만. 대사에 맞춰 손을 움직인다. |
| **백업** | | 사고 나면 스크린샷 슬라이드로 즉시 전환 |

**말하는 사람과 클릭하는 사람을 나누는 게 훨씬 매끄럽다.** 혼자 하면 화면 보느라 말이 끊긴다.
