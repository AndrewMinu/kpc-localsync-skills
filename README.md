# 로컬 싱크 — 부트캠프 스킬

2026 미래형 관광인재 양성교육 부트캠프 (로컬 싱크)
2박 3일 동안 지역 관광 문제를 찾아 **작동하는 AI 서비스 데모와 피칭**까지 만드는 스킬 13개.

---

## 1. 먼저 이것부터 (설치 전에)

Codex를 열고 이 한 문장만 던지세요.

```
강릉 1박2일 코스 짜줘
```

조건은 아무것도 주지 마세요. 나온 결과는 **그대로 두세요.** 곧 씁니다.

## 2. 설치

```bash
npx skills@latest add AndrewMINU/kpc-bootcamp -a codex -g -y
```

한 번만 하면 됩니다. 스킬 13개와 주제카드 25장, 전국 기준데이터가 같이 깔립니다.

## 3. 첫 실습 (10분)

아까 받아둔 '강릉 코스'를 들고, 이번엔 스킬로 다시:

```
$trip-course
```

맨몸 결과와 뭐가 다른지 팀이 직접 비교하는 실습이 여기서 벌어진다.

## 4. 시작

```
$bootcamp-start
```

여기서부터는 안내해주는 대로 따라가면 됩니다. 헷갈릴 때 언제든 `$bootcamp-start`를 다시 부르면
지금 어디까지 왔고 다음이 뭔지 알려줍니다.

## 준비물

| | |
|---|---|
| **Codex** | 주 작업 도구. 스킬은 `$이름`으로 부릅니다 |
| **공공데이터포털 인증키** | [data.go.kr](https://www.data.go.kr) 회원가입 → 마이페이지 > 인증키 발급 현황 → **일반 인증키(디코딩)**. 무료입니다 |

> ⚠ **키는 빨리 만들어두세요.** 발급·활용신청이 승인돼도 실제로 되기까지 **최대 1시간**이 걸립니다.
> `$bootcamp-start`가 팀 세팅 끝에 시키는 것도 이 때문입니다.

키는 **채팅에 그대로 붙여넣으면** 스킬이 알아서 씁니다. 환경변수 설정 몰라도 됩니다.
다만 파일·발표자료·깃에는 넣지 마세요.

## 스킬 13개

`$bootcamp-start`가 순서를 안내하니 **외울 필요는 없습니다.** 아래는 지도입니다.

### 온보딩

| | 스킬 | 하는 일 |
|---|---|---|
| **0** | `$trip-course` | 조건을 묻고 실데이터를 불러 여행 코스를 짭니다. 첫 실행이면 **맨몸 vs 스킬 비교 실습**을 진행합니다 — 이게 3일 내내 쓸 감각입니다 |
| | `$bootcamp-start` | 환영·팀 세팅·역할 배정·키 안내. 이후엔 **"지금 어디고 다음이 뭔지"** 를 알려주는 길잡이 |

### 1일차 — 문제를 찾는다

| | 스킬 | 하는 일 |
|---|---|---|
| **1** | `$topic-select` | 팀의 문제의식 + 주제카드 25장 = **우리 팀 주제카드**. 카드는 메뉴판이 아니라 재료입니다 |
| **2** | `$api-select` | 그 주제를 확인하려면 어떤 데이터가 필요한지 골라 **활용신청**하고 작동을 확인합니다 |
| **3** | `$region-select` | 이 문제가 가장 선명한 **지역**을 후보 데이터를 보며 팀이 정합니다 |
| **4** | `$data-collect-validate` | 실제로 데이터를 받아 가설을 두들깁니다. **방문 → 체류 → 소비** 어디서 끊기는지 |
| **5** | `$idea-sketch` | 검증된 문제를 풀 **솔루션 아이디어**를 팀 회의로 좁힙니다 |
| **5b** | `$idea-validate` | 핵심 기능 **딱 1개**로 좁히고 잘라낸 걸 기록합니다 ← **1일차 저녁까지 여기** |

> 💡 **왜 API가 지역보다 먼저인가** — 활용신청 반영에 1시간이 걸려서, 주제만 정해지면 먼저 걸어두고
> 그 사이에 지역을 토론합니다. 지역 정하고 신청하면 4단계 한복판에서 한 시간을 기다리게 됩니다.

### 2일차 — 만든다

| | 스킬 | 하는 일 |
|---|---|---|
| **5c** | `$design-setup` | 색·서체를 10분에 확정해 `design.md`로 박아둡니다. 화면 짜면서 색 고민하면 둘 다 망가집니다 |
| **6** | `$prototype-build` | 클릭되는 데모 `prototype.html` → **Codex Sites 공개 배포**까지 |
| **6b** | `$pitch-deck-build` | 발표 슬라이드 `pitch-deck.html`. 장수·순서·내용은 팀이 짭니다 |

### 3일차 — 보여준다

| | 스킬 | 하는 일 |
|---|---|---|
| **6c** | `$pitch-prep` | 시연 시나리오·대본·예상 질문·**통합 리허설**. 덱만 좋고 발표가 무너지는 팀이 매년 나옵니다 |

### 언제든 (선택)

| 스킬 | 하는 일 |
|---|---|
| `$deep-dive` | 사용자 인터뷰·여정 매핑·유사사례. 아이디어가 얕다 싶을 때 끼워 넣습니다 |

## 팀 역할 — 가이드 · 네비게이션 · 드라이버

`$bootcamp-start`가 첫 실행 때 이름과 함께 배정합니다. **작업 분담이 아니라 무엇을 끝까지 되물을지**의
문제입니다. 이후 모든 스킬이 **이름을 불러** 그 사람에게 질문을 던집니다.

| 역할 | 지키는 것 | 입에 달고 사는 질문 |
|---|---|---|
| **가이드** | 우리가 풀려는 게 누구의 무슨 문제였나 | *"그거 우리 사용자가 진짜 겪는 일이에요?"* |
| **네비게이션** | 화면·발표에 나가는 모든 숫자의 출처와 기준시점 | *"이 숫자 어디서 왔어요? 언제 기준이에요?"* |
| **드라이버** | 진짜 돌아가는가, 진짜 보이는가 | *"지금 눌러서 되는 거 맞아요? 빔에서 보여요?"* |

2인 팀은 가이드·네비게이션을 각자 맡고 **드라이버는 공동**입니다.

## 같이 깔리는 자료

전부 `bootcamp-start/references/` 안에 있습니다. 스킬이 알아서 읽으니 직접 열 일은 많지 않습니다.

| | |
|---|---|
| `cards/` | **주제카드 25장** — 데이터로 확인된 관광 이슈 패턴. 문제·페르소나·가설·후보지역표·추천 MVP |
| `data/` | **전국 234개 시군구 × 31개 지표** — 공급·방문·숙박비중·소비·다양성·동선. 읽는 법은 `data/README.md` |
| `guides/api-setup.md` | 한국관광공사 **API 14종**의 활용신청 목록과 실측 호출 레시피 |
| `guides/data-catalog.md` | 카드 밖 주제·심화 과제용 외부 데이터 출처 |
| `_context-template.md` | 진행 상태 파일 `context.md`의 원본 |

> 기준데이터는 **AI가 추천의 근거로 조용히 확인하는 용도**입니다. 숫자를 직접 받아 검증하는 건
> 4단계에서 팀이 자기 키로 합니다 — 그 발견의 경험이 이 부트캠프의 핵심입니다.

## 막힐 때

**스킬이 안 불러져요**
설치가 안 됐거나 Codex를 다시 켜야 합니다. `npx skills@latest add ...`를 다시 돌려보세요.

**`Unauthorized`가 떠요**
키나 활용신청이 아직 반영 안 된 겁니다. **최대 1시간**, 기다리면 저절로 풀립니다.
그동안 다음 단계로 넘어가세요 — 그러라고 API를 2단계에 둔 겁니다.

**`SERVICE_ACCESS_DENIED`가 떠요**
그 API만 활용신청이 빠진 겁니다. `$api-select`가 어느 것인지 이름을 알려줍니다.

**지금 어디까지 왔는지 모르겠어요**
`$bootcamp-start`. 상태를 요약하고 다음 한 걸음을 알려줍니다.

**그래도 안 되면** — FT를 부르세요. 5분 넘게 같은 데서 막혀 있으면 그게 맞습니다.
